# コンポーネント実装ルール

## Server/Client境界

- `use client`はServer/Clientコンポーネントの境界にのみ記述する。汎用コンポーネントに安易に記述しない

## データ取得

- サーバーで取得するデータは、値を使うコンポーネントで取得する。値を使うのがClient Componentなら、直近の祖先Server Componentで取得してpropsで渡す（判断理由: `docs/decisions/fetch-data-in-consuming-server-component.md`）
  - 上位で取得した値を、その値を使わない中間コンポーネントを経由して渡さない。同じデータを複数のコンポーネントが使う場合も、それぞれで取得する
  - 前提: 取得関数がReactの`cache()`等で同一リクエスト内の重複を排除していること。排除されない取得関数は上位で1回取得して渡す
  - 例外: 一覧取得の各要素のデータは、一覧を描画するコンポーネントから各項目のコンポーネントへ渡してよい
  - 例外: データ取得を持たない汎用の表示コンポーネントには、使う側からpropsで渡す

## Props

- Props Drillingが発生し、かつそのPropsが他箇所で未使用・単一コンポーネントのみに渡っている場合→型は`React.ComponentProps`で取得。参照先は実際にレンダリングしている直近の子コンポーネント（孫以降まで遡らない）
- 特定要素の機能拡張のみが目的のコンポーネント→`React.ComponentPropsWithRef`で型定義
- Props型はConsumer-driven（使用側の要求）で決める。上流（APIスキーマ等）の型に引きずられない

## JSX

- 条件分岐で返すJSXの外側要素は同じタグに統一する
- 外側をフラグメントにするか`div`等でくくるかは、返すトップレベル要素のうち通常フローに配置されるものの数で決める
  - 数える対象: どの状態でも（初期表示だけでなく、エラー表示・展開・読み込み中等も含む）通常フローに出るトップレベル要素。テキストノードも含む
  - 数えない対象: `showModal()`で開く`<dialog>`（トップレイヤー）、`createPortal`、`position: fixed`/`absolute`、`display: none`/`hidden`、`null`を返すコンポーネント
  - 0〜1個→フラグメントのまま、または要素を直接返す。ラッパーを足さない
  - 2個以上になり得る→`div`等でくくる
  - 例外: 親のレイアウトへ複数要素を差し込む設計のコンポーネント（`<li>`群、`<tr>`、グリッドセル群等）→意図してフラグメントにする
  - `children`等、親から渡された内容で数が変わる場合→そのコンポーネントが親に対して何要素として振る舞う設計かで決める
- className: 変数・条件分岐は最後に記述
